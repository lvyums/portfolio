Agent 工具调用

Agent 拥有 6 种工具能力，根据用户意图自动选择并执行。支持多工具链式调用（搜索→选课）。

# Agent 工具调用流程 "帮我选CS101" → search_courses("CS101") → add_course(course_id=1) → "已成功添加 CS101" # 工具注册表 TOOL_MAP = { "search_courses": _exec_search_courses, "add_course": _exec_add_course, "remove_course": _exec_remove_course, ... }
2

上下文感知

Agent 理解用户专业、年级、已选课程等上下文，实现个性化交互。支持确认词快速操作。

# 上下文构建 system_prompt = f""" 学生：{major} {grade}，兴趣：{interests} 已选课程：{current_selections} """ # 确认词机制 if message.strip() in CONFIRM_WORDS: # 用户说"好的" → 自动添加缓存课程 _exec_add_course(user.id, cached[0]["id"])
3

三级降级策略

LLM 工具调用 → 直接回复 → 规则引擎，确保服务始终可用。

try: # Level 1: LLM 工具调用 response = llm.chat_completion(messages, tools=TOOLS) tool_calls = parse_tool_calls(response) except Exception: # Level 3: 规则引擎兜底 return _keyword_fallback(user, message) # 规则引擎支持： # "帮我选CS101" → 正则提取课程代号 # "退掉数学课" → 模糊匹配已选课程
4

策略模式选课

不同课程类型采用独立选课策略，新增课程类型只需添加策略类（开闭原则）。

class EnrollmentStrategy(ABC): @abstractmethod def validate(self, user, course, existing): ... @abstractmethod def execute(self, user_id, course): ... _strategies = { "专业课": MajorCourseStrategy(), "公共课": GeneralCourseStrategy(), # ≤5门 } _default = ElectiveCourseStrategy()

Challenges

技术挑战与解决方案

1

Agent 工具调用可靠性

▼
问题

LLM 返回的工具调用格式不稳定，可能返回无效 JSON、错误参数或超时。

解决方案

多层容错：①解析多种格式（代码块/直接JSON/花括号匹配）②工具参数智能补全（支持数字ID/课程代号/搜索缓存）③工具执行失败自动降级到规则引擎。

def _resolve_course_ids(self, tool_args, message, user_id): for key in ("course_id", "old_course_id", "new_course_id"): cid = tool_args.get(key) if isinstance(cid, str) and not cid.isdigit(): course = db.query(Course).filter(Course.code.ilike(cid)).first() if course: tool_args[key] = course.id if not tool_args.get("course_id"): if user_id in self._last_search: tool_args["course_id"] = self._last_search[user_id][0]["id"]
2

自然语言意图识别

▼
问题

用户表达多样化："帮我选CS101"、"退掉数学课"、"推荐一些编程课"、"好的"（确认词）。

解决方案

正则匹配 + 关键词分类 + 搜索缓存 + 确认词机制，四级处理确保意图准确识别。

KEYWORD_MAP = { "add": ["选", "加", "选课", "想上"], "remove": ["退", "删", "不要", "退选"], "list": ["选了哪些", "我的课", "已选"], "recommend": ["推荐", "建议", "什么课好"], } CONFIRM_WORDS = ["好的", "可以", "行", "确认", "添加"]
3

策略模式解耦选课规则

▼
问题

不同课程类型的选课规则混杂在 if-else 中，新增课程类型需要修改核心代码。

解决方案

使用策略模式，将每种课程类型的选课规则封装为独立策略类。通过策略注册表动态分发，新增课程类型只需添加策略类并注册。

def _get_strategy(course_type) -> EnrollmentStrategy: return _strategies.get(course_type, _default_strategy) # 新增课程类型只需： _strategies["实验课"] = LabCourseStrategy() # 零改动扩展
4

前端状态多组件同步

▼
问题

选课操作后，课程列表、已选标记、学分统计、推荐列表等多个组件需要同步更新。

解决方案

使用 Pinia 观察者模式，Store Action 修改 State 后，Vue 响应式系统自动检测变化并更新所有订阅组件。

// 选课操作后自动触发视图更新 const selectionStore = useSelectionStore() await selectionStore.addCourse(course) // CartSummary、CatalogView、Sidebar 自动响应
