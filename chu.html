Challenges

技术难点与解决方案

开发过程中遇到的核心技术挑战及对应的解决方案

01

开发/生产数据库无缝切换

+
问题：本地开发使用 SQLite，生产部署使用 PostgreSQL，连接字符串和 SQL 方言存在差异。

方案：通过环境变量 DATABASE_URL 实现自动切换，优先读取环境变量，未设置时回退到 SQLite。Docker Compose 通过 environment 注入 PostgreSQL 地址，本地开发零配置。
02

RAG 知识库检索不触发

+
问题：智谱 AI API 调用时，模型有时跳过知识库检索，直接用自身知识回答，导致领域准确性不足。

方案：设置 tool_choice: {"type": "retrieval"} 强制触发检索；编写专用 prompt_template 要求优先使用知识库内容；降低 temperature 至 0.2；开启引文标注验证检索是否生效。
03

Flask-Admin 路由冲突

+
问题：Flask-Admin 初始化时注册路由，若在 app.py 路由定义之前初始化，会与自定义路由冲突。

方案：将 Admin 初始化延迟到所有路由注册之后，逻辑独立到 admin.py 模块，app.py 末尾调用 init_admin(app)。
04

容器首次启动数据库初始化

+
问题：Docker 容器首次启动时数据库为空，表结构和初始数据需要手动导入。

方案：编写 migrate.py 统一迁移脚本，支持 init（建表）、migrate（导入数据）、validate（校验完整性）三个子命令，配合 Docker Compose 的 depends_on 确保数据库就绪后再执行。
05

悬浮球拖动与点击事件冲突

+
问题：AI 助手悬浮球需同时支持点击跳转和长按拖动，但 click 事件在 mouseup 后立即触发，拖动后也发生跳转。

方案：引入 data-dragging 标记位，长按 300ms 进入拖动模式后设置标记，click 事件中检查标记决定是否阻止跳转，拖动位置保存到 localStorage 持久化。
